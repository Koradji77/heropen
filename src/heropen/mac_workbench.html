本机记忆库

这里只展示已有记忆库的真实统计；存储模式请在上方“按 Agent 分别设置”中调整。库数与客户端数不一定相同。

存储模式 · 按 Agent 分别设置

每个 Agent 各自独立，改动只影响所选 Agent，不会波及其他人。这里说的是存储粒度：自动＝本地规则识别重要决定、内容长度和信息量，决定保存时机（非云端大模型）；十轮一存＝每十轮保存一批；步步为营＝每个完整话轮分别存入一条。每轮＝用户输入＋助手完整回复。请注意三点区别：(1) 粒度≠采集方式——只有宿主逐轮回调或后台定时读取真正提交了话轮，粒度才会生效，仅发现 MCP 配置不代表自动存档已接通；(2) 每轮≠工作断点——“步步为营”指每个完整话轮一条记忆，不是每次工具操作生成进度断点（断点请用 session_checkpoint）；(3) 切换模式不会立即归档旧尾批——已有待存轮不会因为切到“步步为营”而自动落档，需要下一个新轮提交或显式保存才会触发。由定时读取驱动时，是扫描到该轮后才归档，不保证回复刚结束就立刻写入。显式添加记忆仍立即保存。

自动读取对话 · 本机摄取

部分客户端会把真实对话写在本机记录里（ZCode 的 rollout、WorkBuddy 的 projects），heropen 可以直接读取，不必等它逐轮提交。此处决定是否让后台定时读取：开启后按间隔自动补交完整话轮；“仅试算”只统计不写入（此时显示的“预计可提交”不代表已写库），便于先看清将要提交什么。只读取本机记录，不改客户端配置、不安装钩子；重复读取不会重复计数；注入块（系统提醒、任务通知等）不是用户发言，会被剔除；只有确认回复已完成的轮次才会被采集，中途流式文本不会被当成完整回复。注意：后台读取依赖面板服务运行，仅连接 MCP 或切换保存模式并不会启动它；面板关闭后采集停止。关闭自动时不会自动写入。

本机 AI 客户端

客户端数与记忆库数不同：一个客户端可使用多个库，多个客户端也可共享一个库。“发现配置”仅表示发现 heropen 配置项，不代表已接入。连接状态以客户端会话进程是否存活为准：会话进程存在即显示“已连接”，进程退出才显示“连接已结束”，因此空闲等待不会让它变成断开。“最近调用”单独标注，仅表示 15 分钟内调用过工具，与连接本身无关。身份以“是谁启动了这个连接进程”为准（追溯进程来源，而非客户端自报名称）：来源与绑定一致标注“来源已验证”；追溯不到时退回客户端自报名称；来源指向另一个客户端则视为不匹配、不算已连接。这不是在线心跳或密码学认证，也不证明自动存档已接通。只展示 HEROPEN_AGENT 与 HERO_PEN_DIR，不读取密钥文件、不改写配置。WorkBuddy 仅核对 ~/.workbuddy/mcp.json（不使用 ~/.mcp.json）；Hermes 核对 ~/.hermes/config.yaml 的 mcp_servers（缺少 PyYAML 时标记未解析）；ZCode 优先核对 ~/.zcode/cli/config.json 的 mcp.servers，仅文件不存在时回退 ~/.agents/mcp.json 的 mcpServers，并展示实际检查来源；支持服务器字典或带显式 name 的列表。安装痕迹和共享配置均不能证明 ZCode 已接入。
